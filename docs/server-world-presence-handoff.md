# คำแนะนำถึงเซิร์ฟเวอร์: world presence ยังไม่ตามตัวผู้เล่นจริง

เอกสารนี้สรุปสัญญาที่คลายเอนต์ production ใช้จริง และสิ่งที่เทส 2 เซสชันพบบน `https://pocketmonster-game.web.app/` → `https://nustanakritwithai.github.io/PocketMonster/` เมื่อ 2026-08-29

อย่าใส่ token, cookie, Firebase UID, launch ticket, หรือป้ายชื่อแบบ Guest+hex ลงในล็อก/PR

## สิ่งที่ทำงานแล้ว

- Guest สองเซสชัน (หน้าต่างปกติ + Incognito) เข้า Ranch Hub ได้
- แชทช่อง `WORLD` ส่งถึงกันได้ทั้งสองทางบนซ็อกเก็ตเดียวกัน
- คลายเอนต์มี `POCKETMONSTER_WORLD_STATE()` และส่งตำแหน่งทุก 250ms หลังออธซ็อกเก็ตสำเร็จ
- ตำแหน่งโลคัลขยับตามการเดินจริง

## สิ่งที่ยังไม่ทำงาน

- ไม่มีโมเดล 3D ของผู้เล่นอื่น มีแค่ป้าย HTML สีฟ้า (`.remote-world-player`)
- ทั้งสองหน้าต่างเห็นป้าย `kind=guest` ค้างที่พิกัดโลก `x=8`, `z=5`
- พิกัดนั้นไม่ใช่ตำแหน่งจริงของทั้งสองคนที่เทส
- เดินออกไปไกลแล้วป้ายไม่ขยับตาม มีแค่การซ่อนป้ายเมื่อออกนอกกล้อง (คำนวณฝั่งคลายเอนต์จากพิกัดเก่า)

สรุปสั้นๆ: แชทบน `/ws/chat` ใช้ได้ แต่รายการผู้เล่นในโซนไม่ได้อัปเดตจาก `world-pos` สด หรืออัปเดตแล้วส่งกลับคนละรูปที่คลายเอนต์ทิ้งเงียบๆ

## เวอร์ชันตอนเทส

- คลายเอนต์ Pages: `8.4.0-github.181f48907aebba9a1bbd984a51001d7223536458`
- API `GET /api/version`: `environment=staging`, `deployedRelease.version=8.4.0-world-presence.20260829`, commit `bb11094036633baf968b76136ae2d39c6df53c7d`

## สัญญาที่คลายเอนต์คาดหวัง

ซ็อกเก็ต: `wss://157.85.96.139/ws/chat`

เฟรมแรกหลัง `open`:

```json
{ "token": "<session token>" }
```

จากนั้นทุก 250ms:

```json
{ "type": "world-pos", "zone": "hub", "x": 0.0, "z": 0.0, "dir": 0.0 }
```

- `zone` ของ Ranch Hub คือสตริง `hub` ตรงๆ ไม่ใช่ `Ranch Hub` หรือ `ranch-hub`
- `x` / `z` เป็นตัวเลขโลก Three.js ของตัวละคร
- `dir` คือ `player.rotation.y` (ยังไม่ใช้วาดป้าย แต่ส่งมาแล้ว)

คลายเอนต์รับเฉพาะข้อความแบบนี้:

```json
{
  "type": "world-snapshot",
  "payload": {
    "zone": "hub",
    "players": [
      { "id": "stable-player-id", "name": "display name", "x": 1.25, "z": -3.5 }
    ]
  }
}
```

กติกาที่ทำให้คลายเอนต์ทิ้งทั้งเฟรมโดยไม่ขึ้น error:

1. `type` ต้องเป็น `world-snapshot` เท่านั้น
2. ข้อมูลต้องอยู่ใน `payload` — ถ้าส่ง `zone` / `players` ที่รูท คลายเอนต์จะได้ `payload === undefined` แล้ว return
3. `payload.zone ===` โซนปัจจุบันของคลายเอนต์ แบบเทียบสตริงตรง (`hub` ≠ `Ranch Hub`)
4. แต่ละคนต้องมี `id` ที่ truthy และ `x`, `z` ที่ `Number.isFinite` — ขาดอย่างใดอย่างหนึ่ง = ข้ามคนนั้น
5. `name` ถ้าไม่มี จะโชว์ `ผู้เล่นออนไลน์`
6. คนที่หายจาก `players` จะถูกลบป้ายออก

แชทบนซ็อกเก็ตเดิมยังต้องยิง `{ "type": "chat" }` เพื่อให้คลายเอนต์ไปดึง `/api/chat/messages` — อย่าทำให้เฟรมแชทพังตอนเพิ่ม presence

## สิ่งที่เซิร์ฟเวอร์ควรตรวจ

1. **รับ `world-pos` จริงหรือไม่**  
   หลังออธด้วย `{ token }` แล้ว เก็บ `zone,x,z,dir` ของเซสชันนั้นทุกครั้ง ไม่ใช่แค่ครั้งแรก

2. **อัปเดตพิกัด ไม่ใช่ค้างสปอว์น**  
   เทสนี้ป้ายค้างที่ `8,5` ทั้งสองหน้าต่าง ทั้งที่โลคัลเดินไปประมาณ `(-10, 12)` และ `(-10, 5)`  
   ถ้าเซิร์ฟเวอร์มีจุดเกิดเริ่มต้นที่ `8,5` ให้ตรวจว่าไม่ได้ล็อกคนทั้งหมดไว้ที่นั่น

3. **กระจายคนอื่นในโซนเดียวกัน ไม่รวมตัวเอง**  
   ผู้รับควรได้รายการคนอื่นที่ `zone` ตรงกัน  
   อย่าใส่ผู้รับลงใน `players` ของตัวเอง (ไม่งั้นจะมีป้ายทับตัวเอง)

4. **ห่อเป็น `payload` ตามสัญญาด้านบน**  
   ถ้าอัปเดตสดส่งคนละ shape กับสแนปช็อตแรก อธิบายได้ว่าทำไมมีป้ายค้างแต่เดินแล้วไม่ขยับ

5. **Guest / anonymous ต้องเข้า presence ได้**  
   เทสใช้ Guest สองคน แชทผ่านแล้ว แปลว่าโทเคนเซสชันใช้กับซ็อกเก็ตได้อยู่แล้ว  
   อย่าล็อก presence ไว้เฉพาะบัญชีอีเมลหรือ allowlist

6. **อย่าให้บอท/ผู้เล่นค้างแทนคนจริง**  
   ระหว่างเทสมีบอทแชท `Atlas` ในช่องโลก  
   ถ้าบอทหรือเซสชันค้างถูกปักที่ `8,5` แล้วคนจริงไม่ถูกใส่ในรายการ คลายเอนต์จะเห็นแค่ป้ายนิ่งคนเดียว

7. **TTL เมื่อหลุดซ็อกเก็ต**  
   ปิด/รีคอนเนคต้องลบคนนั้นออกจากสแนปช็อต ไม่เก็บตำแหน่งเก่าไว้ไม่มีกำหนด

8. **ความถี่**  
   คลายเอนต์ส่งทุก 250ms เซิร์ฟเวอร์จะ throttle ส่งออกได้ (ประมาณ 200–500ms) แต่ค่าที่เก็บต้องเป็นตำแหน่งล่าสุด

9. **ธงเวอร์ชัน**  
   ถ้า presence พร้อมแล้ว ใส่ `worldPresence` ใน `GET /api/version` → `features` จะไล่ง่ายกว่าตอนนี้ที่มีแต่ `chatWebSocket`

10. **อย่าผูกกับ write gate**  
    Presence เป็นพิกัดสาธารณะในโซน ไม่ใช่การเซฟผู้เล่น  
    ตอนนี้คลายเอนต์ production ยังปิด `vpsWrites` / `playerDataWrites`

## วิธีพิสูจน์ฝั่งเซิร์ฟเวอร์ (ไม่ต้องเปิด DevTools ผู้เล่น)

ใช้สองเซสชัน Guest ในโซน `hub`:

1. ยืนยันว่ามีเฟรม `world-pos` เข้ามาสองไอดี หลังออธซ็อกเก็ต
2. ให้ไอดี A เดินจน `x` หรือ `z` เปลี่ยนอย่างน้อย ~8 หน่วย
3. สแนปช็อตที่ส่งให้ B ต้องมี A ที่พิกัดใหม่ ไม่ใช่ `8,5`
4. สแนปช็อตที่ส่งให้ A ต้องมี B ที่พิกัดจริงของ B
5. `payload.zone` ต้องเป็น `hub`
6. ตัดซ็อกเก็ต A แล้วป้าย A ต้องหายจากสแนปช็อตของ B ภายในไม่กี่วินาที

ถ้าขั้น 1 ไม่มีเฟรมเข้า = ยังไม่ parse / ไม่รับ `type=world-pos`  
ถ้าขั้น 1 มีแต่ขั้น 3 ค้าง = เก็บครั้งแรกแล้วไม่อัปเดต หรือกระจายคนละคน  
ถ้าขั้น 3 ถูกแต่คลายเอนต์ไม่ขยับ = shape ไม่ใช่ `{ type, payload }` หรือ `zone` ไม่ตรง `hub`

## สิ่งที่คลายเอนต์ไม่ได้ทำ (อย่าคาดหวังจากเกมตอนนี้)

- ไม่ส่งโมเดล 3D / สกิน / ทิศทางไปวาดตัวละครคนอื่น
- ไม่กรองผู้เล่นตามระยะ แค่เทียบโซน
- ไม่โชว์ error ถ้าสแนปช็อตผิดรูป
- ไม่มี REST สำหรับ presence — มีแต่ซ็อกเก็ตแชทเส้นเดียว
